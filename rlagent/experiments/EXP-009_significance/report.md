## Caveats (apply to every number above)

- Single-intersection twin: no corridor coordination or platoon arrivals (Poisson within each 5-min count), which under-credits GDOT's coordinated Peachtree timing.
- Demand = GDOT's counted 5-min volumes (stop-bar detector counts); right turns are not counted.
- Twin capacity: driver imperfection sigma = 0.2 (SUMO default 0.5), so a through lane discharges about 1,920-2,010 veh/h of green in a cyclic queue-discharge test, at or slightly above the HCM base saturation flow (1,900) and above typical adjusted field values (~1,700-1,800) -- slightly optimistic. It is a standard-value calibration, not a fit to measured discharge at this intersection (intersections/7065/timing/capacity_check/README.md). Some PM count bins on Sep 21/23/24 exceed any physical discharge and are likely repeated pulses from set-back count detectors in stop-and-go queues; they are kept as recorded (fidelity policy).
- Webster is one all-day plan designed for the PM peak (no time-of-day plans); it can be beaten off-peak by any adaptive controller.
- RL: idealised detection (whole-approach lane occupancy, route-based left-turn calls); skips uncalled lefts (GDOT's actuated controller can too; Webster cannot).
- Real timing (actuated): SUMO's NEMA controller runs P1 before P2 (GDOT runs it after); the fixed exact-order row differs in both order and actuation, so the gap between the two rows bounds their combined effect. Its gap-out settings were fitted to Oct 2 records — a test day — which favours real timing on that day.
- Hardware parameters for all controllers come from GDOT's records, partly from a test day: minimum greens (RL, Webster, real) from the Oct 2 Timing & Actuation records; pedestrian walk/clearance times from the Oct 2 16:00 charts (cross-checked against all recorded windows).
- Saturdays: not chronologically held out (they fall inside the training/validation calendar span, but none was used for training or selection); Webster is the weekday-PM design applied unchanged; GDOT's weekend plans F/G/H run with gap-out settings fitted on a weekday and have no Timing & Actuation record of their own.
- Lane configuration not yet verified against the SR-237 widening construction state (see CLAUDE.md).
- All runs use SUMO 1.27.1, pinned in the project's uv environment (pyproject.toml) regardless of the system install; matrix.py refuses to run on any other version. An earlier run (archived, not used here) was on an OS-upgraded SUMO 1.28.0, which segfaulted intermittently; 1.27.1 has hit the same transient segfault at least once (matrix.py retries a crashed run up to 3x, which is deterministic and verified to reproduce), so the retry logic -- not the version alone -- is what makes these runs reliable.
- On the hand-built twin, the size of RL's advantage over Webster depends on this calibration; its direction does not. With sigma 0.5 (archive/v3_2026-10-15_sumo1.27.1_sigma0.5) RL beat Webster by 9.1 s/veh on weekdays and 6.1 on Saturdays; with sigma 0.2 the margin is smaller (see above) -- mostly because Webster's Peachtree-SW left was near breakdown at the lower capacity.
- Pedestrians are not simulated; Webster and RL respect pedestrian minimum greens every cycle.
- SUMO version: Eclipse SUMO sumo 1.27.1.
